При отзыве EXE существующие bridge закрываются после перечитывания config (каждые 2 секунды) и ближайшей проверки flows (250 ms); новые пакеты сверяют текущую идентичность процесса. Смена VPN закрывает старые flows. Старые прямые TCP-сессии без нового SYN продолжают исходный маршрут. Лимиты: 1024 TCP / 4096 UDP; лишние новые выбранные flows отбрасываются.

Второй пакет: runtime-профиль исключает локальные/pushed route и DNS directives; route-noexec/route-nopull сохраняют настройку самого интерфейса. DNS остаётся системным, VPN-only имена могут не разрешаться. Сертификаты/ключи копируются в отдельный частный каталог; include cycles, отсутствующие файлы, hooks/plugins и management overrides отклоняются. Adapter GUID/index/IPv4/gateway берутся из native management событий принадлежащего UI OpenVPN, backend сверяет PID/FILETIME и LUID каждые 250 ms. Новая sessionId отзывает старые flows даже с прежним IP/index.

Патч 1.0.1: vendored `windivert` принимает SOCKET/FLOW metadata с нулём payload bytes; timeout отменяет конкретный OVERLAPPED и дожидается завершения перед освобождением памяти. Регрессии библиотеки включены в workspace CI. UI показывает exit code и путь к частному `redirector.log`; файл и одна ротация ограничены 2 MiB каждый, panic/error chain сохраняются. Наличие процесса теперь входит в readiness. Установка патча и трафик через него требуют отдельной проверки.

1.3.1: добавлен выключенный по умолчанию экспериментальный PIA-подход с собственной
реализацией: временная замена общей Dnscache, перенаправление IPv4 DNS/53 по EXE
и отдельная служба восстановления с журналом. Запросы выбранных приложений
используют метаданные DNS текущей VPN-сессии. Глобальное влияние на кеш остаётся;
собственный DoH/DoT не заменяется. Неопределённое владение DNS и выбранный
IPv6/loopback DNS блокируются. Измерения на настоящем VPN и crash/reboot ещё
требуются; Windows VPN Platform отложен. Наличие VPN не доказывает DNS-изоляцию.

В экспериментальном режиме неприписываемые TCP/UDP IP-фрагменты блокируются,
включая трафик невыбранных приложений. Нужны отдельные проверка MTU/fragmentation
и ограниченная сборка фрагментов либо более точная атрибуция до снятия ограничения.

Отдельные ограничения: без подтверждённого management gateway сессия не объявляется готовой; gateway больше не угадывается по on-link строкам. Принудительное завершение процесса не гарантирует удаление маршрута; отзыв/смена target пока не добавляют специальную RST-инъекцию. Нет подтверждения нагрузочной устойчивости, полной DNS/IPv6-изоляции или совместимости с anti-cheat.

Готово, когда: Критерии исправленных CORE/UI/SEC задач подтверждены автоматическими тестами или сохранёнными измерениями.

### ENG-01

- [ ] **P2 · Проверить ключи TCP flows и ownership по полному tuple.** TcpKey и fallback PID lookup используют local IP/port; добавить сценарий одновременных соединений с общим local endpoint и разными удалёнными адресами. Не объявлять частоту этой коллизии доказанной без стенда.

Готово, когда: Корректно обслуживаются допустимые reused endpoints; ключ учитывает нужные поля и идентичность сессии.

### ENG-02

- [ ] **P2 · Устранить зависимость инъекции ответов от недокументированного поведения.** send_injected устанавливает outbound=true и для ответов remote→app. WinDivert допускает, что это может работать, но не гарантирует такой inbound-on-outbound путь. Проверить supported inbound injection с корректными interface metadata.

Готово, когда: Выбранная схема документирована и проверена на поддерживаемых Windows; нет безусловного утверждения, что текущая схема всегда не работает.

### ENG-03

- [ ] **P2 · Проверить стартовую готовность и сложные сетевые сценарии.** Синхронизировать первичную загрузку config и запуск capture; определить поведение уже открытого TCP при включении VPN, входящих TCP, fragmentation, MTU/PMTU, ICMP, локальных прокси и unconnected UDP.

Готово, когда: Для каждого сценария есть тест и явно описанное поведение: поддержка, отказ или осознанный обход.

### PERF-01

- [ ] **P2 · Измерить задержки и пропускную способность redirector.** recv_wait до 50 ms может задерживать обслуживание bridge при отсутствии outbound-пакетов; также есть синхронный PID lookup/retry. Измерить p50/p95/p99, CPU и память, затем выбрать механизм пробуждения и batching.

Готово, когда: Опубликован воспроизводимый benchmark по TCP/UDP и игровой нагрузке; изменение принимается по измерениям.

### OBS-01

- [ ] **P2 · Сделать диагностику доступной пользователю.** В 1.0.1 реализованы ограниченные логи redirector, panic/error chain, exit code и путь в UI, сохранение после shutdown. Осталось: очистка старых каталогов логов, ограничение/экспорт OpenVPN logs, единый экспорт с удалением секретов, версии всех компонентов и удобное открытие диагностики. Полная приёмка OBS-01 ещё открыта.

Готово, когда: Без консоли можно узнать причину AUTH_FAILED, отсутствующего драйвера, ошибки маршрута и разрыва IPC.

### OBS-02

- [ ] **P2 · Привести телеметрию к единой семантике.** UDP out считает IP packet bytes, in — payload; TCP считает payload. active_tcp_flows/active_udp_flows заполняются нулями, adapter_name пуст. Определить session/lifetime totals и поведение при завершении PID.

Готово, когда: Счётчики совпадают с контрольной передачей, единицы и период накопления описаны, доступные поля заполнены реальными значениями.

### PROD-01

- [ ] **P2 · Согласовать режимы fail-open и IPv6.** Fail-open и обход IPv6 уже явно документированы; это не новые баги. Решить, нужен ли выбираемый fail-closed для отмеченных приложений и как показывать ограничения IPv6. Отключение IPv6 только на VPN-профиле не блокирует прямой IPv6 физического адаптера.

Готово, когда: UI ясно показывает действующий режим; для выбранной политики есть тест VPN down и dual-stack.

### PROD-02

- [ ] **P3 · Определить поддерживаемые возможности OVPN.** Отдельно решить поддержку encrypted private keys, challenge/MFA, multiple remotes, TAP и DCO, а также допустимых исполняемых hook/plugin directives в импортируемом профиле.

Готово, когда: Есть явная матрица профилей; неподдерживаемые возможности диагностируются до запуска, поддерживаемые проверены.

### ARCH-01

- [ ] **P3 · Разделить привилегированный backend и обычный UI.** После исправления текущего WPF-пути оценить service mode и запуск UI без администратора. Rust ui — заглушка, supervisor — прототип; не считать их уже готовой альтернативой.

Готово, когда: Принято архитектурное решение с моделью владения процессами, конфигом и IPC; прототипы либо развиваются, либо явно исключены из продуктовой сборки.

## Экспериментальный supervisor

Не требуется включать этот прототип в ближайший релиз. Если выбирается его развитие:

- [ ] **EXP-01 · P2** — Подтверждение применения начальной policy и стратегия admission потомков без гонки. [Причина и критерий](REVIEW.md#exp-01).
- [ ] **EXP-02 · P3** — Корректный Windows argv encoder вместо частичного экранирования. [Причина и критерий](REVIEW.md#exp-02).
- [ ] **EXP-03 · P3** — Откатывать созданный процесс при неудачном assign; RAII до успешного resume. [Причина и критерий](REVIEW.md#exp-03).

## Матрица приёмки

| Сценарий | Ожидаемый результат | Связанные задачи |
| --- | --- | --- |
| Большой TCP upload/download, медленный consumer, малые очереди | Полное совпадение SHA-256, без зависания и потери байтов | CORE-01, CORE-02 |
| TCP FIN/half-close/RST, отмена handshake | Сохранение семантики EOF, своевременный cleanup | CORE-03, CORE-12 |
| Тысячи тихих UDP flows, пустая datagram | Нет накопления задач/handles; пустое сообщение доставлено | CORE-07, CORE-14 |
| PID reuse, UDP port reuse, удаление EXE | Никаких унаследованных правил или старых владельцев | CORE-04…CORE-06 |
| Late gateway, ADD failure, existing default route | Честная readiness, retry, сохранность чужих маршрутов | CORE-08, CORE-09 |
| Переподключение с новым IP/index, два VPN | Target соответствует профилю; старые bridges закрыты | CORE-11, CORE-15 |
| Отказ background task/драйвера/status pipe | Ограниченная остановка/recovery; нет busy loop, доступен Stop | CORE-10, CORE-13, UI-11 |
| Local redirect-gateway, pushed /1, DNS, IPv6 | Выбранное поведение изоляции измерено для listed/unlisted apps | UI-03, DOC-02, PROD-01 |
| Launcher→child→grandchild с ранним connect | Поведение соответствует обещанной политике потомков | DOC-01, EXP-01 при включении |
| Connect×2, Cancel, timeout→retry, switch profile | Один управляемый процесс и один набор сессионных ресурсов | UI-02 |
| Certificate-only, auth-user-pass, external files, override | Валидные поддерживаемые профили работают без фиктивных полей | UI-05…UI-07 |
| Duplicate EXE/PID, malformed config/Snapshot, I/O error | Нет падения UI, восстановление последней корректной конфигурации | UI-04, UI-08, SEC-05 |
| Другой local user, MIC levels, fake server, slow IPC clients | Доступ только предусмотренному клиенту, ограничение ресурсов | SEC-02…SEC-06 |
| Credentials после success/error/crash/restart | Нет постоянной plaintext-копии; ACL подтверждены | SEC-01 |
| Чужой VPN, второй UI, ошибка Job | Чужие процессы не затронуты, собственных сирот нет | UI-01, UI-09 |
| Чистая install, upgrade, uninstall, ошибка MSI | Корректный driver/core, верные exit codes, отсутствие чужого cleanup | BUILD-01, BUILD-02, UI-01 |
| Сборка из другой папки; обновление vendor; битый кеш | Предсказуемый состав артефактов, проверка целостности | BUILD-03…BUILD-06 |

Реальные проверки драйверов, маршрутов и установки проводить на выделенной Windows VM. В результате этого ревью ни одна строка acceptance-матрицы не считается уже пройденной целиком.
