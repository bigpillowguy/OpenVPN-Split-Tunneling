## Рекомендуемый порядок работ

1. **Подготовить воспроизводимую проверку.** QA-01, QA-02, BUILD-06, UI-10. В этой среде сначала нужны Rust, .NET SDK и Inno Setup; текущий .NET runtime не заменяет SDK.
2. **Убрать ошибки установки и владения ресурсами.** BUILD-01, UI-01, SEC-01, SEC-03. Проверить чистую VM и соседний независимый VPN.
3. **Восстановить корректность сетевого ядра.** CORE-01…CORE-10; затем CORE-11…CORE-15. Сначала целостность TCP, потом жизненный цикл flows/PID/routes и shutdown.
4. **Упорядочить VPN-сессии и изоляцию.** UI-02, UI-03, UI-09, UI-11, SEC-02, SEC-04…SEC-06. Управление должно оставаться доступным при отказе телеметрии.
5. **Довести профили, настройки и совместимость.** Остальные UI/BUILD, DOC-01…DOC-03; отдельно принять решения PROD-01/PROD-02.
6. **Провести acceptance и только затем выпускать стабильный релиз.** Нет открытых P1; успешны тесты ниже, чистая установка/обновление/удаление; README соответствует проверенному поведению.

Пункты относятся к зависимостям работ, а не оценке сроков. P1 означает блокирующий приоритет для стабильного релиза, а не то, что каждый пользователь уже наблюдает этот отказ.

## Инфраструктура, измерения и продуктовые решения

### QA-01

- [ ] **P1 · Создать Windows CI и воспроизводимую сборку.** В репозитории нет CI; найдены только два roundtrip-теста IPC. Зафиксировать Rust/MSVC/Windows SDK/.NET SDK/Inno Setup, добавить cargo fmt, clippy, tests, .NET build/tests, publish и проверку состава installer. В release использовать Cargo --locked и контролируемое восстановление NuGet.

Готово, когда: Чистый checkout собирается автоматически; PR получает результаты проверок; installer воспроизводимо связан с commit.

### QA-02

- [ ] **P1 · Создать изолированный сетевой интеграционный стенд.** Windows VM с управляемым OpenVPN и тестовыми TCP/UDP endpoints: SHA-256 передачи в обе стороны, half-close, ограничение скорости, PID/port reuse, child admission, DNS, IPv6, смена адаптера и teardown.

Готово, когда: Критерии исправленных CORE/UI/SEC задач подтверждены автоматическими тестами или сохранёнными измерениями.

### ENG-01

- [ ] **P2 · Проверить ключи TCP flows и ownership по полному tuple.** TcpKey и fallback PID lookup используют local IP/port; добавить сценарий одновременных соединений с общим local endpoint и разными удалёнными адресами. Не объявлять частоту этой коллизии доказанной без стенда.

Готово, когда: Корректно обслуживаются допустимые reused endpoints; ключ учитывает нужные поля и идентичность сессии.

### ENG-02

- [ ] **P2 · Устранить зависимость инъекции ответов от недокументированного поведения.** send_injected устанавливает outbound=true и для ответов remote→app. WinDivert допускает, что это может работать, но не гарантирует такой inbound-on-outbound путь. Проверить supported inbound injection с корректными interface metadata.

Готово, когда: Выбранная схема документирована и проверена на поддерживаемых Windows; нет безусловного утверждения, что текущая схема всегда не работает.

### ENG-03

- [ ] **P2 · Проверить стартовую готовность и сложные сетевые сценарии.** Синхронизировать первичную загрузку config и запуск capture; определить поведение уже открытого TCP при включении VPN, входящих TCP, fragmentation, MTU/PMTU, ICMP, локальных прокси и unconnected UDP.

Готово, когда: Для каждого сценария есть тест и явно описанное поведение: поддержка, отказ или осознанный обход.

### PERF-01

- [ ] **P2 · Измерить задержки и пропускную способность redirector.** recv_wait до 50 ms может задерживать обслуживание bridge при отсутствии outbound-пакетов; также есть синхронный PID lookup/retry. Измерить p50/p95/p99, CPU и память, затем выбрать механизм пробуждения и batching.

Готово, когда: Опубликован воспроизводимый benchmark по TCP/UDP и игровой нагрузке; изменение принимается по измерениям.

### OBS-01

- [ ] **P2 · Сделать диагностику доступной пользователю.** Сохранять ограниченные по объёму логи redirector и OpenVPN, причины failed/degraded, версии backend/driver, поддержку экспорта с удалением секретов. Сейчас ошибки старта подавляются, redirector пишет в невидимый stdout.

Готово, когда: Без консоли можно узнать причину AUTH_FAILED, отсутствующего драйвера, ошибки маршрута и разрыва IPC.

### OBS-02

Готово, когда: Счётчики совпадают с контрольной передачей, единицы и период накопления описаны, доступные поля заполнены реальными значениями.

## Матрица приёмки

| Сценарий | Ожидаемый результат | Связанные задачи |
| --- | --- | --- |
| Большой TCP upload/download, медленный consumer, малые очереди | Полное совпадение SHA-256, без зависания и потери байтов | CORE-01, CORE-02 |
| TCP FIN/half-close/RST, отмена handshake | Сохранение семантики EOF, своевременный cleanup | CORE-03, CORE-12 |
| Тысячи тихих UDP flows, пустая datagram | Нет накопления задач/handles; пустое сообщение доставлено | CORE-07, CORE-14 |
| PID reuse, UDP port reuse, удаление EXE | Никаких унаследованных правил или старых владельцев | CORE-04…CORE-06 |
| Late gateway, ADD failure, existing default route | Честная readiness, retry, сохранность чужих маршрутов | CORE-08, CORE-09 |
| Переподключение с новым IP/index, два VPN | Target соответствует профилю; старые bridges закрыты | CORE-11, CORE-15 |
| Отказ background task/драйвера/status pipe | Ограниченная остановка/recovery; нет busy loop, доступен Stop | CORE-10, CORE-13, UI-11 |
| Local redirect-gateway, pushed /1, DNS, IPv6 | Выбранное поведение изоляции измерено для listed/unlisted apps | UI-03, DOC-02, PROD-01 |
| Launcher→child→grandchild с ранним connect | Поведение соответствует обещанной политике потомков | DOC-01, EXP-01 при включении |
| Connect×2, Cancel, timeout→retry, switch profile | Один управляемый процесс и один набор сессионных ресурсов | UI-02 |
| Certificate-only, auth-user-pass, external files, override | Валидные поддерживаемые профили работают без фиктивных полей | UI-05…UI-07 |
| Duplicate EXE/PID, malformed config/Snapshot, I/O error | Нет падения UI, восстановление последней корректной конфигурации | UI-04, UI-08, SEC-05 |
| Другой local user, MIC levels, fake server, slow IPC clients | Доступ только предусмотренному клиенту, ограничение ресурсов | SEC-02…SEC-06 |
| Credentials после success/error/crash/restart | Нет постоянной plaintext-копии; ACL подтверждены | SEC-01 |
| Чужой VPN, второй UI, ошибка Job | Чужие процессы не затронуты, собственных сирот нет | UI-01, UI-09 |
| Чистая install, upgrade, uninstall, ошибка MSI | Корректный driver/core, верные exit codes, отсутствие чужого cleanup | BUILD-01, BUILD-02, UI-01 |
| Сборка из другой папки; обновление vendor; битый кеш | Предсказуемый состав артефактов, проверка целостности | BUILD-03…BUILD-06 |

Реальные проверки драйверов, маршрутов и установки проводить на выделенной Windows VM. В результате этого ревью ни одна строка acceptance-матрицы не считается уже пройденной целиком.
